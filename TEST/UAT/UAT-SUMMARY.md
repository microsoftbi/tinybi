## 2. 测试范围与策略

被测对象为「交叉高亮」交互：点击某视觉对象的图元后，同字段分组的其它视觉对象同步响应——命中项保持不透明，未命中项变暗（透明度 `0.25`），**不做行过滤、不改变聚合与总计**，且高亮为**瞬时态**、不写入项目文件。

采用三层测试策略，兼顾精确性与可维护性：

| 层级 | 目标 | 手段 |
| --- | --- | --- |
| 逻辑层 | `cellOpacity` / `toggleSelection` 的精确语义 | 纯函数直调，无 DOM |
| 组件层 | 各图表/透视表/地图的渲染接线（透明度、点击、可点击性） | jsdom 渲染 + 断言产物 DOM |
| 外壳层 | `DashboardView` 对高亮生命周期的管理（清除时机、不持久化） | 替换 `ReportCanvas` 为可编程替身 |

> 关于 Recharts：jsdom 无布局引擎、无法测量容器尺寸，真实图形无法渲染。因此图表用例将 Recharts 基础组件替换为轻量替身，把每个 `<Cell>` 渲染为带 `fill-opacity` / class / `onClick` 的 DOM 节点，从而**确定性校验数据接线**；像素级渲染外观不在本报告范围（见第 7 节）。

## 6. 关键验证证据

以下为脚本中被固化的**确定性断言**（基于 `sales.csv` 样例数据）：

- **基准聚合正确性**（高优先级用例的前提）
  - 城市 sum(销售额)：上海 250 / 北京 178 / 广州 156 / 深圳 195
  - 城市 sum(利润)：上海 63 / 北京 42 / 广州 35 / 深圳 48
  - 地区 sum(销售额)：华东 250 / 华北 178 / 华南 351
- **高亮不变聚合**（UAT-HL-03）：进入/退出高亮两次渲染的透视表全文完全一致；行总计 967、列总计 [779, 188] 保持不变。
- **透明度量值**（UAT-HL-01/02/17~25）：命中图元 `fill-opacity = 1`，未命中 `= 0.25`（`DIM_OPACITY`），无数据地图区域恒为 `1`。
- **字段隔离**（UAT-HL-15）：按「城市」高亮时，按「地区」分组的图表所有图元保持 `1`。
- **不可变暗对象**（UAT-HL-27）：折线/面积/堆叠面积/散点/表格/数值卡 不产生任何可高亮图元。
- **地图未匹配区域**（UAT-HL-25）：无数据区域（如天津）保持不透明、光标为 `cursor-default`、点击不触发回调；有数据区域点击回传**数据标签**（如「上海」）而非地理名。
- **清除与持久化**（UAT-HL-11~14、28）：点击空白 / Esc / 切换仪表盘 / 删除来源图表 均清除高亮；`dashboardStore` 序列化结果（模拟 `.biproj`）中不含任何 `highlight` 键，重新挂载后无残留。

## 7. 已知限制与未覆盖项

以下内容**不在本次自动化范围**，需在 Tauri 原生窗口中人工验收：

1. **像素级渲染外观**：jsdom 无法测量容器尺寸，Recharts 被替身化；柱/饼/树/漏斗/径向等图形的实际绘制与视觉观感需人工确认。
2. **⌘/Ctrl 键的浏览器/系统级行为**：脚本通过注入 `metaKey` 校验接线，真实键盘修饰键行为需人工验证。
3. **内置地图数据的真实匹配率**：脚本以固定 5 要素假 GeoJSON 验证逻辑，真实各省市名称与内置数据的匹配覆盖需人工抽验。
4. **原生文件读写链路**：`.biproj` 的真实保存/加载经由 Tauri IPC，脚本以 store 序列化近似验证「不含高亮」，端到端需人工确认。

对照 `UAT.md` 第 6 节，上述均为**已归档、不影响本次验收**的既有产品限制或验收方式边界。
